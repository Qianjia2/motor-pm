# MotorPM 项目管理平台 — Docker 部署说明

> 本包用于把"电机系统设计项目管理系统"(FastAPI + Vue3,端口 5002)部署到公司 NAS。
> 部署完成后,平台不依赖任何个人电脑,电脑关机不影响平台运行。

---

## 一、包结构

```
MotorPM_Docker_Deploy/
├── Dockerfile                  # 镜像构建脚本(自动构建前端+后端)
├── docker-compose.yml          # 容器编排(端口、数据卷、健康检查)
├── requirements.txt            # 后端依赖清单
├── .dockerignore
├── src/
│   ├── backend_v2/             # 后端全部代码
│   └── frontend/               # 前端源码(构建时自动编译)
├── data/                       # 初始数据(数据库 + 业务配置,部署时自动用)
└── uploads/                    # 上传文件目录(初始为空,需手动迁移旧数据)
```

---

## 二、前提条件

| 项目 | 要求 |
|---|---|
| NAS 型号 | **x86 架构**(Intel/AMD CPU,型号带 "+" 后缀,如 DS920+/DS1621+;带 "j" 的 ARM 机型不支持) |
| 套件 | **Container Manager**(原 Docker 套件)已安装 |
| 磁盘 | 建议 ≥ 20GB 空闲(镜像约 1.5GB,uploads 3.5GB,留增长余量) |

> 如何确认:DSM → 套件中心 → 搜索 **Container Manager**,能搜到并安装即可。

---

## 三、部署步骤(约 15 分钟)

### 第 1 步:上传部署包

1. 在 NAS 共享文件夹新建目录,例如:`/volume1/docker/motorpm`
2. 把本部署包内**所有内容**(Dockerfile、docker-compose.yml、src、data、uploads)上传到该目录,保持目录结构不变。

### 第 2 步:迁移旧数据(重要)

**① 上传文件(3.5GB)**
将 NAS 上已有的旧存储目录 `MotorPM_Live\uploads` 下**全部内容**(文件+子目录,不带 uploads 这层外壳)复制到部署目录的 `uploads\` 文件夹内。

**② 数据库(2.7MB,建议更新)**
部署包 `data\` 里已内置一份数据库快照。如部署时平台数据有更新,请从原运行电脑的 `D:\AI\motor-pm\data\motor_pm_v2.db` 复制覆盖。

**③ 知识库索引**
如 NAS 上 `MotorPM_Live\data\` 里有 `kb_*.json` 文件,把它们也复制到部署目录的 `data\` 文件夹(同名文件覆盖即可)。

> 提示:上述复制用 NAS 的 File Station 或 Windows 资源管理器拖拽即可;文件多时用 robocopy 更快。

### 第 3 步:构建并启动

1. 打开 Container Manager → **项目** → **新增**
2. 项目名称:`motorpm`
3. 路径:选择第 1 步创建的部署目录
4. 来源:使用现有的 docker-compose.yml(保持默认)
5. 点击下一步 → 勾选"构建镜像前拉取最新版本"(可选)→ 完成

Container Manager 会自动构建镜像(首次约 5-10 分钟,取决于 NAS 性能)并启动容器。

### 第 4 步:验证

- 浏览器访问 `http://NAS的IP:5002`(例如 `http://10.136.101.13:5002`)
- 登录页正常显示即部署成功;用原账号密码登录,检查:
  - 项目列表、上传的文件是否可见
  - 知识库问答是否可用

## 四、日常运维

| 操作 | 方法 |
|---|---|
| 查看状态 | Container Manager → 容器 → motorpm(绿色=运行中) |
| 查看日志 | 点击容器 → 日志 |
| 重启 | 点击容器 → 重启 |
| 停止 | 点击容器 → 停止 |
| 开机自启 | 无需设置,`restart: unless-stopped` 已自动保证(NAS 重启后自动拉起) |
| 手动命令行 | SSH 进 NAS 后:`cd /volume1/docker/motorpm && docker compose up -d`(启动)/ `docker compose down`(停止)/ `docker compose logs -f`(日志) |

## 五、升级(新版本发布时)

1. 用新版 `src/` 覆盖部署目录中的 `src/`
2. Container Manager → 项目 → motorpm → **构建**(或 SSH 执行 `docker compose up -d --build`)
3. 数据(数据库、uploads)不受影响,不会丢失

## 六、数据备份建议

容器数据全部在 NAS 文件系统上(`./data` 和 `./uploads` 两个目录),建议:

- 开启群晖**共享文件夹快照**(推荐,自动按时间点回滚)
- 或用 **Hyper Backup** 定期备份这两个目录到另一存储/异地
- 两者可同时启用

## 七、常见问题

**Q1: 容器一直"重启中"/启动失败?**
→ 查看容器日志。常见原因:`data` 目录没有写入权限(给容器用户授权,或右键 data 目录 → 属性 → 权限),或数据库文件损坏。

**Q2: 图片/附件上传后,预览打不开?**
→ 确认 `uploads` 目录权限可写,且迁移时保持了 `项目ID/子目录` 的结构不变。

**Q3: OCR(截图文字识别)功能提示"未安装"?**
→ 容器默认未安装 OCR 引擎(体积太大)。需要时:编辑 `requirements.txt`,取消最后一行的注释,重新构建。

**Q4: AI 问答用不了?**
→ 平台支持多种 AI 来源(本地 ollama / 云端 DeepSeek 等)。登录后进入"AI 配置"页面检查:
- 若用**云端** DeepSeek/通义/Kimi:直接在页面填入 API Key 即可(容器可访问外网)
- 若用**本地 ollama**(默认配置指向本机 11434 端口):需要在 AI 配置页把 base_url 改为运行 ollama 那台机器的地址,或另起一个 ollama 容器

**Q5: 想改访问端口?**
→ 编辑 `docker-compose.yml` 中 `ports` 一行,把 `5002:5002` 改成 `新端口:5002`,然后在 Container Manager 中重新"构建"应用配置。

**Q6: 如何开放外网访问?**
→ 平台本身无限制,取决于网络出口:
- 内网访问:直接 `http://NAS_IP:5002`
- 外网访问:需公司防火墙/路由器做端口映射(或走公司 VPN),并建议在反代层加 HTTPS。请与网络管理员沟通。

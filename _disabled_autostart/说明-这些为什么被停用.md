# 这些自启项为什么被停用

2026-09-14 从「启动」文件夹移到这里。**没有删除**，要恢复原样，把文件移回
`%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\` 即可。

## 移走了什么

| 文件 | 原本指向 | 问题 |
|---|---|---|
| `MotorPM.bat` | `python run_v2.py` | 与注册表项重复，重复拉起 `run_v2.py` → 重复看门狗 |
| `MotorPM.lnk` | `start_all.bat` | **会 `taskkill /F /IM ngrok.exe`**，每次开机打断隧道 |
| `start_all - 快捷方式.lnk` | `start_all.bat` | 同上，和上一条是两个入口指向同一个脚本 |
| `MotorPM_AutoStart.vbs` | `python server_watchdog.py` | 只起看门狗、**不 import auto_backup** → NAS 自动备份会静默停掉 |
| `start_all.bat.tmp.2444.597496450883` | （仓库根目录的编辑器临时文件） | 内容是 `taskkill /F /IM python.exe`，双击一下整个平台全灭 |

## 保留的那一条

注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 里的：

```
MotorPM = ...python.exe D:\AI\motor-pm\run_v2.py
```

**只留这一条**，原因：`auto_backup.py` 的备份线程是在**模块导入时**启动的
（`auto_backup.py:43-44`），只有 `run_v2.py` 会 import 它。换成
`vbs → server_watchdog.py` 那条链，NAS 自动备份会无声无息地停掉——这是查的时候
才发现的坑，不是猜的。

## 现在是怎么保证不重复的

不是靠"只剩一个入口"（用户随时可能手滑双击 `run_v2.py`），而是两层代码兜底：

1. `server_watchdog.py` 的 `_acquire_singleton()`——Windows 具名内核互斥体，
   第二只及以后的看门狗自己干净退出。内核负责释放，进程崩溃/被 kill/断电
   都不会留下死锁。
2. `run_v2.py` 启动前探一次 `127.0.0.1:5002/api/health`，通就打印一行然后退出。

所以就算这几条自启项哪天被恢复回去，也不会再出现"多个看门狗互相杀 ngrok"。
